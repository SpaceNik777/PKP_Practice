# Отчёт по практической работе 4. Вариант A

Проект находится в `ПКП-4/Вариант-A`. Он продолжает вариант A из ПКП-3 и сохраняет создание, чтение и постановку заявки в очередь на отправку.

## Что сделано

Добавлен порт `limits.Checker`. Он принимает контекст, идентификатор операции, автора и название лимита. Метод `Application.Submit` проверяет лимит `active-applications-per-author` до изменения агрегата. Если операция запрещена или сервис лимитов недоступен, заявка не переходит в `SUBMITTED`.

HTTP-адаптер вызывает `POST /v1/limits/check`. В запрос отправляются поля `subject` и `limit`. Заголовок `Idempotency-Key` строится как `limit:submit:<application-id>`. Один и тот же ключ используется во всех retry-попытках одного вызова.

Повтор выполняется только при транспортной ошибке, ответе `429` или `5xx`. Между попытками применяется экспоненциальная задержка с jitter. Ответ `allowed:false`, остальные `4xx` и ошибки формата ответа не повторяются.

Одновременные обращения ограничивает fail-fast bulkhead размером 20. Если все места заняты, новый вызов сразу получает `ErrBusy`. Один экземпляр `http.Client` создаётся в точке сборки и переиспользуется адаптером.

Добавлены настройки окружения:

- `LIMITS_URL`, по умолчанию `http://127.0.0.1:8081`;
- `LIMITS_TIMEOUT`, по умолчанию `800ms`;
- `LIMITS_ATTEMPTS`, по умолчанию `3`;
- `LIMITS_BACKOFF`, по умолчанию `50ms`;
- `LIMITS_CONCURRENT`, по умолчанию `20`.

## Проверка

Тест с двумя ответами `503` и последующим успешным ответом зафиксировал ровно три HTTP-вызова. Во всех трёх запросах был одинаковый `Idempotency-Key`.

Тест отмены контекста показал завершение HTTP-вызова с `context.Canceled`. Тест bulkhead запустил 21 вызов при ограничении 20: двадцать запросов дошли до сервера, один получил `ErrBusy`, максимальное число запросов внутри обработчика было равно 20. При ответе `allowed:false` выполнен один HTTP-вызов, retry не было. Отдельный тест прикладного сервиса проверяет, что после отказа лимита заявка остаётся в состоянии `DRAFT`.

Форматирование `gofmt`, статическая проверка `go vet ./...`, тесты `go test ./...` и `go test -race ./...` завершились без ошибок. Для race detector использованы `CGO_ENABLED=1` и MinGW-w64 GCC.
